TUFT DETECTOR - QUICK COMMANDS
==============================

Run these commands from the project folder.


1. SET UP (once)
---------------

cd "/Users/aryandesai/Downloads/Projects/Tufting-Visual-Detection-System"
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r Requirements.txt -r Requirements-train.txt
python -m pip install "git+https://github.com/facebookresearch/sam2.git"


2. MAKE TRAINING LABELS  (SAM 2 labeller)
-----------------------------------------

Photos are first downscaled to --norm-size (default 1400 px long side) so every
tuft is ~15-110 px long, the size the detector limits and the U-Net crops assume.
main.py uses the same default, so training and inference see the same scale.

For each photo, draw a polygon around the instrumented surface (click points,
Enter = done, right-click = undo, Esc = whole image). Everything outside the
polygon is saved as background, which is what teaches the U-Net to ignore sky,
ground, garage doors and other vehicles:

python -m tools.autolabel --images Images/tuft4.jpg --out data/vehicle_review --labeler sam2 --select-roi --polarity auto

Non-interactive alternative (original-image pixels):

python -m tools.autolabel --images Images/tuft4.jpg --out data/vehicle_review --labeler sam2 --roi-polygon "x,y;x,y;x,y;x,y"

--labeler sam2 is STRICT by default: a candidate SAM 2 cannot segment as a compact,
string-like object that matches the candidate is DROPPED, not kept. (The old
behaviour kept every classical proposal, so every classical false positive
became a training label. --keep-sam-disagreements restores it.)

--polarity: dark = dark strings on a light surface, light = light/bright strings on
a dark surface (e.g. orange yarn on a dark window), auto = try both, keep the one
with more tufts. If tufts are a different colour from what you expect, check the
preview in data/<out>/previews/ before reviewing.

tufts3.jpg and tufts6.jpg are AVIF files despite their .jpg names. Convert first:

mkdir -p results/avif-converted
sips -s format jpeg Images/tufts3.jpg --out results/avif-converted/tufts3.jpeg
sips -s format jpeg Images/tufts6.jpg --out results/avif-converted/tufts6.jpeg

Review (click a tuft to reject, shift-click to flip root/tip, right-drag to reject
a box, u undo, s save+continue). NOTE: the brush/"select-only"/--scale options this
file used to describe are not in tools/review_labels.py at the moment, so the review
tool can remove false labels but cannot ADD tufts the labeller missed.

python -m tools.review_labels --data data/vehicle_review

Photos labelled BEFORE --norm-size existed have no "scale" in meta.json; train_unet
warns about them. Re-run autolabel on those photos.


3. TRAIN THE U-NET
------------------

python -m tools.make_synthetic_dataset --out data/synthetic --count 60

python tools/train_unet.py --data data/real_review data/vehicle_review --synthetic data/synthetic --out models/tuft_unet_vehicle.pt --epochs 50 --epoch-size 400 --batch 8 --size 256 --base 16 --device mps

Defaults changed to cut false detections: --pos-weight 2.0 (was 4.0),
--p-positive 0.6 (was 0.8, i.e. more tuft-free "hard negative" crops), and the
suggested threshold is chosen on F0.5 (precision-weighted) instead of Dice.
The log now prints precision (P) and recall (R) each epoch.


4. MEASURE IT  (do this - it is the only way to know it got better)
--------------------------------------------------------------------

Object-level precision/recall on the held-out photos, same split train_unet used:

python -m tools.eval_detection --data data/vehicle_review --backend classical --polarity light
python -m tools.eval_detection --data data/vehicle_review --backend classical --polarity light --no-clean
python -m tools.eval_detection --data data/vehicle_review --backend unet --weights models/tuft_unet_vehicle.pt

(needs >= 2 source photos so a held-out split exists; --split all scores everything)


5. RUN AN IMAGE AND OPEN THE RESULT
-----------------------------------

python main.py --image Images/tuft4.jpg --backend unet --weights models/tuft_unet_vehicle.pt --outdir results --save-mask

Optional extra false-positive filter (needs sam2 installed, slower):

python main.py --image Images/tuft4.jpg --backend unet --weights models/tuft_unet_vehicle.pt --verify-sam2 --outdir results

--threshold defaults to the value the checkpoint's own validation picked
(models/<name>.pt.json); pass it only to override. --no-clean turns off the
"must belong to the main cluster of tufts" filter. --select-roi still gives a
rectangle; use it to exclude surroundings.

Classical backend (no training), pick the polarity that matches your tufts:

python main.py --image Images/sample_tufts1.jpg --polarity dark
python main.py --image Images/tuft4.jpg --polarity light

Open the newest annotated image:

open "$(ls -t results/*_annotated.png | head -n 1)"

The annotated image, mask, and vector CSV are saved in results/.
The detector cannot promise a fixed accuracy on arbitrary images; use step 4.

6. RUN A VIDEO  (video -> frames -> same image detector -> annotated video)
---------------------------------------------------------------------------

Same detector/backends/options as images; just pass an MP4 (detected by extension, or use --video):

python main.py --video Videos/tufts_flight1.mp4 --polarity auto
python main.py Videos/tufts_flight1.mp4 --backend unet --weights models/tuft_unet_vehicle.pt

Outputs in results/ (the default):
  <name>_<time>_annotated.mp4   original video with flow arrows + tuft IDs on every frame
  <name>_<time>_vectors.csv     time history: timestamp_s, frame, tuft_id, root/tip, unit_vector_x/y/z, ...

Video-only options:
  --frame-step N        process every Nth frame (faster; output video has just those frames, at fps/N)
  --max-frames N        stop after N processed frames (quick test run)
  --save-frames         also keep each annotated frame as a PNG in results/<name>_<time>_frames/
  --select-roi / --roi  pick/give the region on the FIRST frame; it is used for every frame
  --no-track            don't carry tuft IDs across frames (IDs are then per-frame numbers)
  --track-dist PX       how far a tuft's root may move between frames and still be the same tuft (30)
  --track-max-missing N frames a tuft may go undetected before its ID is retired (5)

--polarity auto is decided on the first frame and then kept for the whole video.
If ffmpeg is installed (brew install ffmpeg) the output is re-encoded to H.264 so it plays in
browsers/PowerPoint; without it you get OpenCV's mp4v MP4 (plays in VLC/QuickTime).
Offline only - not live/camera input yet.
